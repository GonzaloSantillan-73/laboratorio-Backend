==========================================================================
 PRUEBAS EN POSTMAN - API FERIA DEL PONCHO
==========================================================================

Hacer las pruebas EN ORDEN, de arriba hacia abajo. Cada parte usa datos
que se crearon en las partes anteriores (tokens, ids, etc.).

Cada prueba tiene:
  - METODO y URL      -> copiar en la barra de Postman
  - Token             -> Authorization > Bearer Token
  - Body              -> Body > raw > JSON (copiar y pegar tal cual)
  - Esperado          -> lo que tiene que responder


--------------------------------------------------------------------------
 0. PREPARACION (una sola vez, en la terminal)
--------------------------------------------------------------------------

npx prisma migrate reset
npx prisma generate
node --experimental-strip-types scripts/cargar-localidades.js
node --experimental-strip-types scripts/inicializar-admin.js
npm run dev

Datos que quedan cargados:
  Roles:        1 = ARTESANO, 2 = ADMINISTRADOR
  Rubros:       1 Textil, 2 Cerámica, 3 Platería, 4 Cuero, 5 Madera, 6 Cestería
  Pabellones:   1 Pabellón 1, 2 Pabellón 2, 3 Pabellón 3
  Coordenadas:  ids 1 a 9, del punto (1,1) al (3,3)


--------------------------------------------------------------------------
 VARIABLES DE POSTMAN
--------------------------------------------------------------------------

Crear un Environment en Postman con estas variables (arriba a la derecha
elegir ese Environment). La primera se completa ahora, las demás a medida
que avanzan las pruebas: cada paso dice cuál guardar.

  url             http://localhost:3000/api
  tokenAdmin
  idAdmin
  localidadId
  tokenAna
  idAna
  artesanoAna
  tokenBruno
  idBruno
  artesanoBruno
  tokenCarla
  artesanoCarla
  productoAna
  productoBruno
  standAna
  standLibre
  idElena
  idDiego

Postman reemplaza {{variable}} también adentro del body.

IMPORTANTE: el token vence a los 15 minutos. Si de golpe todo responde
401 "Token inválido, vencido o revocado", volver a hacer el login.

 1. LOGIN Y CUENTA DEL ADMINISTRADOR
==========================================================================

--- 1.1 Login del admin ---
POST {{url}}/usuarios/login
Token: ninguno
Body (poner el email y la password que están en ADMIN_EMAIL y ADMIN_PASSWORD del .env):
{
  "email": "ADMIN_EMAIL_DEL_ENV",
  "password": "ADMIN_PASSWORD_DEL_ENV"
}

==========================================================================
 QUE SIGNIFICA CADA CODIGO
==========================================================================

  200  OK, devuelve datos
  201  Se creó el registro
  204  Se hizo, sin contenido (borrados, logout, retirar rol)
  400  Los datos enviados están mal (Zod)
  401  No sé quién sos: sin token, token inválido, vencido o revocado
  403  Sé quién sos pero no tenés el rol, o tu cuenta está inactiva
  404  No existe, o no es tuyo (productos ajenos, artesanos no aprobados)
  409  Dato repetido o se rompe una regla (último admin, único rol,
       coordenada ocupada, solicitud ya resuelta, registro con relaciones)
